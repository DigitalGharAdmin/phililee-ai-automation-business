# MB02 Workflow 1 — Webhook AI Sheets

## Workflow purpose

This reusable n8n workflow demonstrates a simple commercial automation pattern for
capturing customer or business requests. It receives structured webhook data, sends
the request to an AI model, generates a structured business/customer-support
response, and appends the original request and AI result to Google Sheets.

## Architecture

```text
Webhook
  → OpenAI: Message a model
  → Google Sheets: Append row in sheet
```

The Webhook node accepts an HTTP `POST` request. The OpenAI node processes the
submitted context and message. The Google Sheets node appends one row containing
the request, AI response, classification, and processing status.

## Input fields

| Field | Purpose |
| --- | --- |
| `name` | Demo customer or contact name |
| `business` | Demo business name or context |
| `order_number` | Order reference associated with the request |
| `message` | Customer or business-support request for AI processing |

## Google Sheets output

The workflow maps these columns into the destination sheet:

| Column | Content |
| --- | --- |
| `timestamp` | Time the workflow processed the request |
| `customer_name` | Submitted customer name |
| `order_number` | Submitted order reference |
| `message` | Original submitted message |
| `ai_response` | Structured response generated by the AI model |
| `intent` | AI-generated request category or intent |
| `status` | Workflow processing result/status |

## Safe example request

Use the test URL shown by your own n8n Webhook node. Keep the real URL and any
webhook secret private. This example contains fake demo data only:

```bash
curl --request POST "https://your-n8n-host.example/webhook-test/your-test-path" \
  --header "Content-Type: application/json" \
  --data '{
    "name": "Demo Customer",

  }'
```

## Testing and verification

1. Import the workflow JSON from this folder into a safe n8n development workspace.
2. Configure OpenAI and Google Sheets through n8n's credential manager. Do not put
   credential values directly in nodes or exported files.
3. Create or select a test sheet containing the seven output-column headers listed
   above.
4. Open the Webhook node in test mode and copy its temporary test URL locally.
5. Send the fake example payload, replacing only the placeholder URL in your local
   command.
6. Confirm that the Webhook node receives all four input fields.
7. Confirm that “Message a model” produces an AI response, intent, and status in the
   structure expected by the sheet mapping.
8. Confirm that “Append row in sheet” succeeds and exactly one new row appears.
9. Verify the row contains the fake input data, a non-empty AI response, an intent,
   a status, and a timestamp.
10. Remove the demo row after evidence is captured if the test sheet should remain
    clean.

## Expected successful result

A valid request completes all three nodes without error and creates exactly one
Google Sheets row. The row preserves the submitted customer name, order number, and
message while adding a timestamp, structured AI response, intent, and successful
processing status.

## Security notes

- Never document or commit API keys, OAuth tokens, credentials, webhook secrets,
  Gmail addresses, Firebase tokens, or other secrets.
- Do not expose n8n credential IDs or sensitive account information.
- Store OpenAI and Google credentials only in n8n's credential manager.
- Use fake, non-sensitive data in tests, screenshots, documentation, and demos.
- Review every workflow export for secrets before sharing or committing it.

## Reliability hardening and acceptance evidence

Configuration was verified against the final local raw export. The following normal
and controlled-failure results were manually tested and reported by the project
owner; documentation closure does not rerun live services.

External-service nodes use Retry On Fail with 3 attempts and a 2000 ms wait between
attempts, then Stop Workflow after exhausted retries. The sanitized export makes
the default maximum attempts and stop behavior explicit. The shared error workflow
reference is replaced with `CONFIGURE_SHARED_ERROR_HANDLER`.

- Normal Webhook -> OpenAI -> Google Sheets: PASS.
- OpenAI retry hardening: PASS.
- Google Sheets retry hardening: PASS.
- Shared error workflow configured: PASS.
- Production OpenAI failure notification: PASS.
- Safe notification excluded submitted payloads and credentials: PASS.
- One unique production request produced exactly one Sheets row: PASS.

This test does not prove full exactly-once delivery under ambiguous remote-write
failures. Production-grade idempotency or delivery deduplication can be added when
required; the observed single row is not an exactly-once guarantee.

Only `mb02_workflow_1_webhook_ai_sheets.sanitized.json` is portfolio evidence. Raw exports remain ignored and local-only.
