# Safe screenshot capture guide

Capture later from an authorized, sanitized view. No screenshots are generated or
claimed here. Label offline simulations clearly; do not create fake live evidence.
Inspect every image at full resolution before publishing, including browser chrome,
URLs, tabs, notification popups and side panels. Crop or irreversibly redact private data.

| Shot | Show | Hide or redact |
| --- | --- | --- |
| Core canvas | Node names and major branches in unbound demo | Instance URL, workflow/account IDs, credential sidebar, execution payload |
| Handler canvas | Disabled path and outcome | Account names, recipients, raw trigger/error data |
| Support rules | Sanitized Example Support Co config | Credential selectors, private execution panels |
| Sales rules | sales_team and sales-ack-v1 settings | Production settings, private metadata |
| PowerShell result | Fresh offline DEMO result and simulation label | History, environment variables, home/user paths, auth arguments |
| Requests row | Synthetic schema/example status cells | Real sheet URL/ID, contacts, sharing UI, other rows |
| Duplicate result | reuse/duplicate and no resend counters | Real request/execution IDs and contact fields |
| Reconciliation result | needs_reconciliation/unknown | Provider diagnostics, headers and message IDs |
| Gmail acknowledgement | Only authorized message subject/body and sanitized recipient | Inbox list, account avatar/name, recipient/sender, signatures, message metadata |
| Config JSON | Committed demo configuration | Private configs, adjacent secrets tabs |
| Onboarding guide | Checklist and external binding steps | Local private notes and filenames |
| Validation summary | Counts, PASS and no-live-call statement | Unrelated terminal output and personal paths |

Use [the evidence index](EVIDENCE_INDEX.md) to caption a genuine historical result.
If no safe capture exists, omit it. Never turn a mock or AI-generated image into
purported test evidence. Keep originals private; only reviewed sanitized images
may enter a future portfolio publication step.
